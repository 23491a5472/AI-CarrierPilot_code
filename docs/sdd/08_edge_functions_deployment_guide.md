# Supabase Edge Functions Deployment Guide

This guide covers the deployment, configuration, and testing of the five core AI Edge Functions that power CareerPilot.

---

## 1. Complete Deployment Guide

To deploy your Edge Functions to a live Supabase environment:

1. **Install Supabase CLI** (if not already installed):
   - Mac: `brew install supabase/tap/supabase`
   - Windows: `scoop install supabase`
2. **Login to Supabase CLI**:
   - Run: `supabase login`
   - Create and paste an Access Token from your Supabase Dashboard.
3. **Link your Project**:
   - Run: `supabase link --project-ref <your-project-id>`
4. **Deploy all functions**:
   - Run: `supabase functions deploy`
   - *Alternatively, deploy a specific function: `supabase functions deploy analyze-resume`*

---

## 2. Required Environment Variables

These are the environment variables required in your Flutter application's `.env` file for the app to communicate with Supabase.

```env
# Flutter .env configuration
SUPABASE_URL=https://<your-project-id>.supabase.co
SUPABASE_ANON_KEY=<your-anon-api-key>
```
*(You can find these in Supabase Dashboard -> Project Settings -> API)*

---

## 3. Supabase Secrets List

Edge Functions run in a secure backend environment. They require the **Gemini API Key** to interact with Google's AI, but this key is **never** sent to the Flutter app.

To add the secret to your Supabase project, run the following command from your terminal:
```bash
supabase secrets set GEMINI_API_KEY=your_actual_gemini_api_key
```

You can verify the secret was set correctly by running:
```bash
supabase secrets list
```

## 5. Example Request/Response Payloads

All functions expect a `POST` request with JSON bodies, and they return strict JSON structures generated by Gemini.

### A. `analyze-resume`
**Request:**
```json
{
  "resume_path": "a1b2c3d4/1782087156_resume.pdf",
  "job_description": "We are looking for a Senior Flutter Developer with 5+ years of experience..."
}
```
**Response:**
```json
{
  "ats_score": 88,
  "skills_score": 90,
  "experience_score": 85,
  "format_score": 95,
  "strengths": ["Strong Flutter knowledge", "CI/CD experience"],
  "weaknesses": ["Missing state management keywords"],
  "matched_skills": ["Flutter", "Dart", "Firebase"],
  "missing_skills": ["Riverpod", "GraphQL"]
}
```

### B. `generate-cover-letter`
**Request:**
```json
{
  "resume_text": "I am a mobile developer specializing in Flutter...",
  "job_description": "Senior Mobile Developer at Acme Corp...",
  "tone": "Confident"
}
```
**Response:**
```json
{
  "cover_letter_text": "Dear Hiring Manager,\n\nI am writing to express my strong interest in the Senior Mobile Developer position at Acme Corp. With a proven track record..."
}
```

### C. `generate-skill-gap-report`
**Request:**
```json
{
  "resume_text": "I am a mobile developer...",
  "job_description": "We need a Full Stack Developer..."
}
```
**Response:**
```json
{
```

### D. `generate-interview-questions`
**Request:**

## 6. Testing Commands using cURL

To test an Edge function from your terminal, you need your `SUPABASE_URL` and a valid `JWT_TOKEN` (the token of an authenticated user).

```bash
curl -i --request POST 'https://<your-project-id>.supabase.co/functions/v1/analyze-resume' \
  --header 'Authorization: Bearer <YOUR_JWT_TOKEN>' \
  --header 'Content-Type: application/json' \
  --data '{
    "resume_path": "user_id/test_resume.pdf",
    "job_description": "Senior Developer role"
  }'
```

*(Note: Edge Functions validate the `Authorization` header automatically using Supabase Auth. Unauthenticated requests will be rejected).*

## 7. Production Deployment Checklist

Before going live to app stores, ensure the following:

- [ ] **Database Schema Pushed:** `supabase db push` has been run successfully.
- [ ] **Functions Deployed:** `supabase functions deploy` completed without errors.
- [ ] **Secrets Configured:** `GEMINI_API_KEY` is securely set in Supabase Secrets.
- [ ] **RLS Enabled:** Row Level Security (RLS) is enabled on `profiles`, `usage_limits`, `subscription_status`, and `saved_jobs` tables so users can only access their own data.
- [ ] **Storage Buckets Created:** The `resumes` bucket exists, and Storage Policies dictate that users can only upload/read their own files.
- [ ] **Auth Providers Configured:** Email/Password (and any social logins like Google/Apple) are configured in the Supabase Dashboard.
